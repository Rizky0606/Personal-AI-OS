## Temuan Fase 4 (auth)

### Keputusan yang saya ambil karena dokumen tidak merinci

- [ ] **Scope menurut jenis perangkat:** `android` dan `desktop` mendapat `app`; `worker` mendapat `worker` dan `llm` (omp di PC memakai `/llm/v1`). Endpoint `/llm/v1/*` sendiri belum ada (Fase 5), jadi pengecekan scope `llm` dan `worker` baru dipakai di sana. Ubah `SCOPES_BY_KIND` di `modules/auth/tokens.ts` bila pembagiannya berbeda.
- [ ] **Satu login = satu perangkat baru.** Login ulang dari perangkat yang sama membuat baris `devices` baru (yang lama tetap aktif sampai dicabut dari halaman Perangkat). Perlu dedup (nama + jenis) atau ID perangkat dari klien bila daftar cepat membengkak.
- [ ] **Refresh token berformat `<deviceId>.<acak>` dan kedaluwarsa 90 hari sejak rotasi terakhir (sliding),** bukan 90 hari tetap sejak login. Perangkat yang dipakai rutin tidak pernah diminta login ulang; yang diam 90 hari harus login ulang.
- [ ] **Pemakaian ulang bersifat ketat, tanpa masa tenggang.** Bila respons refresh hilang di jaringan dan klien mengulang dengan token lama, perangkat dicabut dan pemilik harus login ulang. Dua refresh bersamaan dengan token yang sama diperlakukan sama. Klien harus menyimpan token baru sebelum memakainya dan tidak boleh mengulang refresh otomatis. Masa tenggang pendek (mis. 10 detik, jawaban yang sama) bisa ditambahkan bila ini mengganggu di jaringan seluler.
- [ ] **Kode TOTP sekali pakai:** langkah yang sudah dipakai (dan yang lebih lama) ditolak. Dua login dalam 30 detik yang sama berarti yang kedua harus menunggu kode berikutnya.
- [ ] **Pesan gagal login sama untuk password salah, TOTP salah, dan akun belum ada** (`invalid_credentials`), dan password selalu dihitung lewat argon2 (termasuk hash palsu) agar waktu respons tidak membocorkan keadaan akun.
- [ ] **`AUTH_SECRET` satu rahasia untuk dua tujuan** (tanda tangan JWT dan enkripsi secret TOTP, diturunkan terpisah lewat HKDF). Mengganti nilainya mencabut semua token dan membuat TOTP tersimpan tidak terbaca, jadi perlu `owner:init --reset`.
- [ ] **`owner_account` tidak ada di "Model data inti"** (satu baris, dijaga constraint). `devices` mendapat `refresh_expires_at` dan `revoked_at`; perangkat dicabut dengan menandai `revoked_at` (baris dipertahankan untuk audit), bukan dihapus.
- [ ] **Setiap request terproteksi membaca baris `devices`** agar pencabutan berlaku seketika (bukan menunggu token 15 menit habis). `last_seen_at` diperbarui paling sering sekali per menit.
- [ ] **`owner:init` di TTY** meminta konfirmasi kode TOTP sebelum menyimpan (agar salah pindai tidak mengunci pemilik). Tanpa TTY (pipa) password dibaca dari stdin dan tidak ada konfirmasi.

### Keterbatasan yang diketahui

- [ ] **Rate limit di memori:** hitungan hilang saat gateway restart dan tidak dibagi antar-instance. Cukup untuk satu proses di satu VPS. Login dibatasi per IP (5 per menit); belum ada penguncian global terhadap serangan dari banyak IP. IP klien dibaca dari `X-Forwarded-For` hanya bila datang dari loopback (nginx), jadi vhost nginx wajib mengirim `X-Forwarded-For` dan `X-Real-IP` apa adanya dari klien.
- [ ] **Request tanpa token valid tidak dihitung di batas umum** (batas berjalan setelah autentikasi); verifikasi JWT murah, tetapi lonjakan tebakan token ditangani nginx/fail2ban.
- [ ] **Belum ada** penyimpanan token di klien (Fase klien), halaman Perangkat, notifikasi saat perangkat baru login, dan rotasi `AUTH_SECRET` tanpa mencabut semua token.
- [ ] **Contracts:** hanya daftar error OpenAPI yang bertambah (403 untuk scope dan 429 untuk rate limit pada endpoint terproteksi). Skema request/response tidak berubah.
- [ ] **Argon2id memakai parameter minimum OWASP (m=19 MiB, t=2, p=1).** Bisa dinaikkan; hash lama tetap terverifikasi karena parameter ada di string hash.

## Temuan Fase 6 (chat umum, adapter, WebSocket)

### Hermes: yang dipakai dan yang masih tidak terverifikasi

- [ ] **Adapter memakai `POST /v1/chat/completions` (stream), bukan `/v1/runs`.** Dokumentasi resmi Hermes (dibaca ulang di fase ini) mendefinisikan `POST /v1/runs` (`input`, `session_id`, `instructions`, balasan `{run_id, status}`) dan `POST /v1/runs/{id}/stop`, tetapi tidak mendefinisikan format SSE `/v1/runs/{id}/events` maupun payload `message.delta`, `run.failed`, dan `run.cancelled`. Chat completions adalah format OpenAI standar dan terdokumentasi lengkap. **Konsekuensi:** cancel hanya memutus koneksi; apakah Hermes ikut menghentikan run-nya belum terverifikasi (VERIFICATION.md sudah mencatat ini). Bila ternyata tidak, pindah ke `/v1/runs` + `stop` (hanya `packages/adapters/src/hermes.ts` yang berubah).
- [ ] **Semua perilaku Hermes di fase ini diuji terhadap server tiruan,** bukan Hermes asli (belum terpasang di mesin ini). Yang perlu dicek di VPS: (1) `X-Hermes-Session-Id` benar-benar memuat ulang transkrip di chat completions stateless, karena adapter hanya mengirim pesan baru; (2) `finish_reason` dan `[DONE]` seperti di dokumentasi; (3) cancel menghentikan run; (4) `hermes.tool.progress`.
- [ ] **Event tool belum dipetakan.** Event SSE bernama `hermes.tool.progress` dilewati karena bentuk payload-nya tidak terdokumentasi, jadi chat umum belum menampilkan langkah tool. `capabilities()` melaporkan `approvals`, `steer`, `checkpoints` = false; `steer` dan `resolveApproval` melempar `unsupported`.
- [ ] **`model` dikirim sebagai `hermes-agent`** (atau nilai `model` dari pesan). Hermes mengabaikannya kecuali `direct_model_requests: true`; pemilih model di UI belum berpengaruh pada Hermes.
- [ ] **`X-Hermes-Session-Key` = `owner`** (tetap) agar memori jangka panjang konsisten lintas percakapan, sesuai rekomendasi VERIFICATION.md. `hermes_session_id` = `aios-<conversationId>`, disimpan di `conversations` saat pesan pertama.
- [ ] **Hermes tidak menerima berkas:** pesan dengan bagian `file` ditolak 400 `files_not_supported` sampai ada alur lampiran (`POST /files`).

### Keputusan yang saya ambil karena dokumen tidak merinci

- [ ] **Alur status run chat mengikuti diagram penuh:** `queued → routing → preparing → running → completed`, masing-masing satu event `run.status`, ditambah `route.decided` (role `general`, confidence 1) di antara `routing` dan `preparing`. Event terakhir run selalu `run.status` berstatus akhir; `run.completed` dan `error` datang tepat sebelumnya. `message.completed` tiba sebelum `run.completed`.
- [ ] **Seq WebSocket:** channel `run:<id>` memakai `run_events.seq` (bisa diputar ulang). Channel `conversation:<id>` hanya membawa `run.status` run percakapan itu dan channel `user` belum membawa apa pun; keduanya **hanya live** (seq penghitung di memori, `replay:false` di balasan `subscribed`). Setelah sambung ulang, klien memuat ulang lewat `GET /conversations/:id/messages` dan `GET /runs/:id`. API_CONTRACT.md menyebut "seq per channel" tanpa merinci log untuk channel selain run.
- [ ] **`lastSeq` tidak dikirim = hanya event baru** (tanpa replay). Untuk mengambil semua event kirim `lastSeq: 0`.
- [ ] **Pesan server baru di kontrak:** `subscribed` (ack sebelum replay, berisi seq terbaru) dan `error` (`invalid_message`, `not_found`, `too_many_channels`). Konstanta `WS_MAX_CHANNELS = 20` dan `WS_CLOSE_UNAUTHORIZED = 4401` ada di `packages/contracts/src/ws.ts`.
- [ ] **Auth WebSocket lewat header `Authorization` saat handshake** (wscat `-H`, OkHttp). WebView/browser tidak bisa mengirim header di `WebSocket`; klien Tauri harus memakai plugin WebSocket Rust atau kita tambah jalur lain (mis. subprotocol). Query string sengaja tidak dipakai agar token tidak masuk log nginx.
- [ ] **Umur koneksi:** heartbeat 20 detik (ping protokol WebSocket; klien yang tak membalas pong diputus). Pada tiap detak server juga memeriksa masa berlaku access token dan status perangkat; bila habis atau dicabut, koneksi ditutup dengan kode 4401 (`token_expired` / `device_revoked`) dan klien refresh token lalu sambung ulang dengan `lastSeq`. Klien yang terlalu lambat (>1 MiB tertahan) diputus dengan kode 1013; aman karena replay dari database tidak menghilangkan event.

Android tidak punya tombol lampiran sama sekali (tidak ada UI mati). Fase tersendiri: endpoint multipart + penyimpanan + batas 25 MB + validasi mime + pemakaian di run, baru UI-nya.

Penguraian ulang tiap delta masih O(panjang jawaban); bila terasa berat di perangkat nyata, throttle delta ke ±50 ms di ViewModel atau urai hanya blok terakhir.

- Belum ada: suara, pencarian di dalam pesan, ekspor, pemilih model per role (default "Otomatis" mengikuti role), tes Compose UI.

## Temuan Fase 19 (review diff dan checkpoint)

- **Komentar bukan `steer`.** Prompt menyebut komentar dibundel jadi satu pesan steer, tetapi pada `needs_review` proses omp sudah berhenti (steer hanya berlaku untuk run yang berjalan). Komentar dikirim sebagai **run baru di worktree dan branch yang sama** (`run.start` dengan `continueFromRunId`): satu pesan berisi `path:baris — isi` per komentar muncul di percakapan, run lama ditandai `rejected` (tidak ada status "dikembalikan"), dan diff kumulatif tetap terhadap base awal. Nomor baris merujuk ke versi berkas saat ini.
- **Gateway ikut diubah** (seperti Fase 17 dan 18): `POST /runs/:id/review` ada di kontrak tetapi belum ada handler-nya. Ditambahkan beserta frame `review.result`, `WorkerRelay.review` (menunggu 30 detik), dan guard dua keputusan bersamaan (hanya satu yang berlaku; yang lain 409). Kontrak: `ReviewRequest` (+`merge`, `commitMessage`), `ReviewResponse` baru, `ReviewState`/`ReviewFile`/`Checkpoint` untuk IPC lokal.
- **Isi diff tidak lewat gateway**: desktop membaca diff dari worker lokal (`review.get`); gateway hanya menyimpan `diff.updated` (daftar file) dan `checkpoint.created`. Konsekuensinya diff hanya bisa ditinjau dari PC yang menjalankan worker (Android tidak bisa).
- **Bug nyata ketahuan uji dengan omp sungguhan**: omp menjalankan `git` sendiri di worktree, jadi `git add -A` saya pada index worktree bentrok (`index.lock: File exists`). Pembacaan selama dan sesudah run kini memakai **index pribadi** (`GIT_INDEX_FILE=<gitdir>/aios-index` lalu `write-tree`, diff antar-tree) dan mencoba ulang bila ada kunci; index worktree hanya disentuh saat run sudah berhenti (undo, batalkan file, terima). Ada tes regresi dengan `index.lock` sengaja dibuat.
- **Checkpoint** = commit pada ref tersembunyi `refs/aios/cp/<id>` (rantai di atas base), bukan commit di branch: riwayat branch hasil tetap satu commit. Dibuat setelah tiap `tool.finished` sukses bila isi worktree berubah (satu `git add -A` per langkah; di repo sangat besar ini terasa). Undo = `read-tree -u --reset` ke checkpoint atau `base`, dan checkpoint sesudahnya dibuang; hanya saat run tidak berjalan.
- **Terima**: satu commit di branch `aios/…`. Pesan commit: agent diminta mengakhiri jawaban dengan `Commit: <conventional>` (instruksi ditambahkan worker ke prompt sistem, jadi tidak mengubah role di `packages/roles`); bila tidak valid, tebakan dari berkas (test/docs/chore) + kalimat pertama ringkasan; pengguna bisa mengubahnya di dialog. Revisi tidak menimpa pesan run pertama. **Merge** hanya `--ff-only` ke branch kerja saat ini, dan hanya bila working tree (berkas terlacak) bersih serta bukan detached HEAD; selain itu branch dibiarkan dan alasannya ditampilkan (`dirty`, `detached`, `not_fast_forward`). Setelah merge sukses, branch sementara dihapus. Tidak ada merge commit otomatis ke branch pengguna.
- **UI**: tab Diff di panel kanan yang sudah ada (lebar maksimum naik ke 960). Daftar file, unified/split, warna sintaks, komentar per baris, Terima (dialog pesan commit + sakelar merge), Tolak semua (konfirmasi), Kirim N komentar ke agent, Batalkan perubahan file (= "Tolak per file"), tab Checkpoint dengan "Kembali ke sini". Panel terbuka sendiri saat run selesai di depan mata; membuka percakapan lama menampilkan pengingat di atas kolom tulis.
- **Dependensi baru: `highlight.js`** (hanya inti + 12 bahasa) karena prompt mewajibkan syntax highlight; warna dari token desain lewat CSS (`.hljs-*`). Pewarnaan per baris, jadi komentar/string yang membentang beberapa baris tidak selalu berwarna benar.
- **Batas yang disengaja**: komentar hanya pada baris tambah (baris hapus tidak punya nomor baru, dan baris konteks membuat ratusan tab-stop); patch dibatasi 200 file × 200 KB (sisanya ditandai terpotong); "Terima per file" belum ada (hanya batalkan per file); diff langsung selama run belum ditampilkan (hanya event `diff.updated`, dipakai Kanban Fase 20); worktree sisa setelah worker dimulai ulang tidak bisa ditinjau (`review_not_found`) dan belum dibersihkan otomatis.
- **Belum terbukti**: tampilan panel belum dilihat langsung di aplikasi Tauri atau peramban (hanya tes komponen jsdom); uji "komentar → perbaikan" memakai model tiruan yang diskripkan, jadi membuktikan mekanisme (pesan komentar sampai ke model, worktree/branch/checkpoint berlanjut, hanya satu baris yang berubah, commit Conventional dan fast-forward) tetapi bukan kemampuan model nyata memahami komentar.

## Temuan Fase 20 (Kanban AI)

- **Kontrak berubah satu hal**: `POST /tasks/:id/run` kini mengembalikan **kartu**, bukan run. Dengan batas run paralel, kartu bisa mengantre dan belum punya run; kartu antre = status `running` dengan `runId` null (tanpa kolom DB baru). Klien membaca `runId` untuk tahu sudah dimulai atau belum.
- **Kartu mengikuti run lewat `RunObserver`** (runner dan layanan tinjauan memberi tahu "run X berubah"; layanan kartu menyamakan status, branch, role, dan diff stat). Run revisi dari komentar review mewarisi `taskId`, jadi kartu tetap Running. Saat gateway dimulai ulang, kartu yang tertinggal disamakan dengan run-nya (`tasks.start()`) dan antrean dilanjutkan.
- **Batas paralel**: `TASK_MAX_PARALLEL` (default 2) per project, nilainya satu untuk seluruh gateway (belum bisa diubah per project dari UI). Antrean dilayani menurut urutan di kolom Running. Pilihan model per run hanya berlaku bila kartu langsung dimulai; kartu yang antre memakai model bawaan role.
- **Role kartu**: bila kosong, router menebak saat kartu dikerjakan dan hasilnya hanya dipakai bila role coding (selain itu `backend`); role yang dipilih manual harus role coding (400 `role_not_coding`). Kartu yang gagal, dibatalkan, atau ditolak kembali ke Todo dan bisa dikerjakan lagi (percakapan kartu dipakai ulang).
- **Pecah dengan AI** memakai model kecil lewat 9Router (`TASK_MODEL`, default `router-fast`), maksimal 8 kartu, role dibatasi role coding; tidak ada yang disimpan sebelum pengguna memilih.
- **Seret-lepas** memakai HTML5 drag and drop tanpa dependensi baru. Di Windows, Tauri secara bawaan mencegat drag ke jendela, jadi `dragDropEnabled: false` ditambahkan di `tauri.conf.json` (aplikasi belum memakai drop berkas). Alternatif tanpa mouse: Alt + panah pada judul kartu dan menu aksi kartu.
- **Belum ada atau terbatas**: hapus kartu (tidak ada endpoint di kontrak); urutan kolom lain dirapikan server tanpa event per kartu (klien memuat ulang daftar); kartu hanya mengingat run terakhir, tanpa riwayat run; channel `user` hanya live, jadi setelah koneksi putus papan baru segar setelah refetch (fokus jendela atau aksi berikutnya); Android belum punya layar Kanban.
- **Belum terbukti**: tampilan papan belum dilihat di aplikasi Tauri atau peramban (hanya tes jsdom); seret-lepas nyata di WebView2 belum dicoba; dua run paralel diuji di gateway (worker tiruan) dan di git (dua worktree dari repo yang sama dibuat dan di-commit bersamaan), tetapi belum dengan dua proses omp sungguhan sekaligus.

Memakai Edge/Chrome yang sudah ada di PC (`AIOS_BROWSER_PATH` untuk menimpa), tidak mengunduh Chromium. `playwright-core` berjalan di dalam `.exe` Bun (diuji); `chromium-bidi` dikecualikan dari bundel. Dev server dijalankan otomatis oleh tool pertama. Temuan omp (xdev, jendela startup, format approval) ada di VERIFICATION.md.
- **Izin tool browser** dijawab otomatis oleh worker (hanya menyentuh preview localhost run itu); permintaan izin lain tetap ditanyakan.
- **Model tanpa input gambar**: `models.yml` mendeklarasikan `input: [text]`, jadi gambar screenshot tidak sampai ke model. Screenshot dilengkapi **laporan tata letak teks** (elemen di luar viewport, gulir mendatar, isi terpotong) yang dipakai agent untuk memverifikasi. Mengaktifkan gambar butuh informasi kemampuan model dari gateway/9Router.
- **Pilih elemen → composer**: mode inspeksi di Preview menghasilkan selector, `outerHTML` (dipotong 3000 karakter), style terhitung penting, ukuran, dan tangkapan elemen (Playwright, halaman baru di viewport yang sama). Tangkapan hanya pratinjau kecil di composer; **lampiran berkas belum ada** (`POST /files` ditunda), jadi yang terkirim ke agent adalah teks konteks + petunjuk memanggil `browser_screenshot` dengan selector itu. Tangkapan ini bukan keadaan halaman yang sedang dilihat pengguna (halaman dibuka ulang di browser headless).
- **Belum ada / terbatas**: preview hanya untuk project Node dengan skrip di `package.json` (Python/Go/dll. tidak terdeteksi); satu dev server per target (project atau run); console di panel hanya yang dikirim jembatan (bukan log jaringan penuh); selector hasil inspeksi bisa tidak unik pada DOM dinamis; preview tidak tersedia di Android; port tetap dipilih dev server sendiri (kita hanya membaca).
- **Belum terbukti**: tab Preview belum dilihat di aplikasi Tauri (iframe lintas origin, CSP `frame-src`, `postMessage`, dan mode inspeksi hanya diuji di jsdom dan proxy dengan Node); seret/klik mode inspeksi di halaman nyata belum dicoba; dev server nyata (Vite/Next) belum diuji, hanya server Node kecil; model nyata belum mencoba tool ini (skenario omp sungguhan memakai model tiruan yang diskripkan).

## Temuan Fase 22 (terminal, palet, status bar, pembanding, kuota)

- **Terminal = PTY sungguhan tanpa modul native**: `Bun.spawn({ terminal })` (ConPTY di Windows) di sidecar; shell PowerShell (`-NoLogo`) di Windows, `$SHELL`/bash selain itu. Terbukti di `.exe` hasil kompilasi lewat `smoke:sidecar` (membuka shell, mengetik `echo`, keluaran kembali sebagai push). Di Node (tes) PTY tidak ada; tes memakai PTY tiruan. Satu terminal per project atau per worktree run; keluaran terakhir 64 KB disimpan agar tab yang dibuka ulang tidak kosong; maksimal 8 terminal. Env shell dibersihkan dari variabel `AIOS_*`. Terminal run ditutup sebelum worktree dihapus.
- **Terminal itu terminal biasa**: cwd awal hanya folder project atau worktree yang terikat, tetapi setelah itu pengguna bebas `cd` ke mana pun dan menjalankan apa pun, seperti di terminal mana pun. Ini disengaja (alat kerja pengguna sendiri); batas "worker tidak menulis di luar worktree" berlaku untuk agent, bukan untuk ketikan pengguna. Tidak ada persetujuan per perintah di terminal.
- **Dependensi baru**: `@xterm/xterm` dan `@xterm/addon-fit` (diwajibkan prompt). Warna terminal dibaca dari token tema yang aktif.
- **Palet perintah**: tanpa pustaka (tanpa cmdk); pencarian substring bertingkat (awalan label, awal kata, memuat, hint/kata kunci) tanpa toleransi salah ketik. Sumber: perintah, navigasi, panel, percakapan (50 terbaru), project, kartu (project aktif saja), jadwal, model, tema. Pola ARIA combobox + listbox (`aria-activedescendant`). Ctrl+1..6 berpindah layar sesuai urutan rail.
- **Model pilihan sekarang global** (disimpan di `uiStore`, diingat antar sesi) alih-alih per percakapan, supaya "Ganti model" di palet dan status bar konsisten. Role aktif di status bar mengikuti keputusan router untuk jawaban yang sedang tampil, atau pilihan manual.
- **Pembanding model**: endpoint baru `POST /compare` (kontrak berubah). Tanpa streaming, `max_tokens` 1024, batas 90 detik per model. Tidak tercatat di tabel runs, jadi **tidak muncul di halaman Kuota bila sumbernya ringkasan run**; bila 9Router menyediakan usage, tercatat di sana. Tidak menyimpan riwayat perbandingan.
- **Halaman Kuota** membaca `/quota` apa adanya (total, per model, per hari, sumber data). "Kuota sisa" (batas langganan) tidak ada karena `/quota` hanya melaporkan pemakaian; status bar menampilkan pemakaian total, bukan sisa.
- **Belum terbukti**: tampilan terminal/palet/Kuota/Pembanding belum dilihat di Tauri atau peramban (jsdom saja; xterm.js diganti tiruan di tes, jadi rendering, fit, dan tema xterm belum teruji); alur "hanya keyboard" teruji per bagian (Ctrl+K, Ctrl+1..6, panah, Alt+panah di Kanban), tetapi belum dijalani utuh oleh manusia; fokus keyboard di dalam tab Diff (komentar baris) tidak diaudit ulang di fase ini.
- **Belum ada**: Rail tidak punya ikon Kuota/Pembanding (dibuka dari palet, status bar, atau Pengaturan); pembanding tanpa riwayat dan tanpa streaming; palet tidak mencari riset atau isi pesan.

## Temuan Fase 23 (keamanan, backup, observability)

- **Audit** ada di `docs/SECURITY_AUDIT.md`: nol temuan tinggi; satu temuan sedang diperbaiki (gateway menolak `HOST` non-loopback di produksi). Auth/scope diaudit lewat tes yang membaca route yang benar-benar terdaftar (hook `onRoute`) dan mencocokkannya dengan kontrak, jadi route baru tanpa penjagaan menggagalkan CI.
- **Backup/restore/systemd/Kuma/cek versi/tes beban ditulis dan diuji hanya dengan perintah palsu** (`infra/scripts/selftest.sh`, jalan di CI): urutan perintah, retensi, penanganan gagal, dan restore tidak menyentuh database produksi. **Belum pernah dijalankan** dengan restic, Docker, Postgres, atau Oracle Object Storage sungguhan, jadi syarat "restore uji berhasil" di VPS masih harus dijalani sekali (`sudo infra/scripts/restore.sh`, langkah di `docs/VPS_SETUP.md`). Format `pg_restore` dari dump `-Fc`, nama skema migrasi `drizzle.__drizzle_migrations`, dan bendera restic belum dibuktikan di lingkungan nyata.
- **Tes beban belum dijalankan di VPS**: tidak ada akses VPS dari sini, jadi tidak ada angka memori/CPU. Yang ada: skrip (`infra/scripts/loadtest.mjs`) yang menjalankan 5 run chat + 1 riset mendalam dan mengambil sampel `/proc`, diuji alurnya terhadap server palsu. Angka nyata harus dicatat setelah dijalankan di VPS.
- **Halaman Status**: `GET /status` (scope `app`) + layar desktop. Versi gateway/adapter adalah konstanta manual (`apps/gateway/src/version.ts`, `packages/adapters/src/version.ts`) yang perlu dinaikkan bersama rilis. Versi Hermes tidak ditampilkan (Hermes tidak melaporkan versinya lewat `/health`; hanya terjangkau atau tidak). Versi omp dan ketersediaan browser dilaporkan worker lokal (status PC ini); worker lain hanya online/offline dan terakhir terlihat. Antrean job dari pg-boss (`getQueues`); `failed` adalah hitungan bergulir, bukan total seumur hidup.
- **Uptime Kuma** hanya sebagai profil compose `monitoring`; notifikasi Telegram dikonfigurasi di UI Kuma (langkah di VPS_SETUP), bukan lewat file.
- **Nginx**: contoh konfigurasi ditambahkan (`infra/nginx/aios.conf.example`), belum dijalankan.
- **Tes yang bergantung beban**: dua tes jadwal desktop dan satu tes koordinator worker sesekali melewati batas waktu saat seluruh suite berjalan paralel di Windows; lulus bila dijalankan sendiri atau diulang.

## Temuan Fase 24 (E2E, review desain, pengemasan, deploy)

- **E2E desktop (Playwright) memakai UI asli tetapi bukan cangkang Tauri**: build `vite` khusus (`e2e/vite.e2e.config.ts`) mengganti modul `@tauri-apps/*` dengan shim (`e2e/shims`) yang meneruskan HTTP, WebSocket, dan IPC ke server kendali Node. Yang diuji sungguhan: UI, gateway, worker, dan omp (stack di `e2e/harness/stack.ts`); Hermes, 9Router, dan SearXNG palsu. **Tidak teruji**: kode Rust (Credential Manager, sidecar spawn, updater), CSP Tauri, dan jendela asli. Spec coding dilewati bila omp tidak terpasang. Jalankan: `pnpm --filter @aios/e2e e2e` (CI: job `e2e-desktop`, Chrome).
- **Postgres tertanam (`embedded-postgres`) butuh ICU versi lama (`libicuuc.so.60`) yang tidak ada di Ubuntu 24.04** (runner GitHub Actions maupun beberapa VPS/distro terbaru) — `initdb` gagal `error while loading shared libraries`. `e2e/harness/stack.ts` sekarang membaca `TEST_DATABASE_URL` (sama seperti job `check`/tes integrasi gateway) dan melewati binary tertanam kalau diisi; CI (`job e2e-desktop`) mengisinya lewat servis `postgres:16`. Tanpa `TEST_DATABASE_URL`, tetap jatuh ke Postgres tertanam seperti semula (untuk mesin yang ICU-nya cocok).
- **Review desain**: axe-core (WCAG 2.0/2.1 A/AA) di tiap layar, terang dan gelap, plus lint desain statis (`apps/desktop/src/designLint.test.ts`). Temuan diperbaiki: kontras `text-3` dan `accent` terang, `aria-pressed` pada radio, label tautan kuota, animasi skeleton dan reduced-motion. Review manual dengan skill UI (rams/better-interface) **tidak dijalankan**; yang dipakai adalah pemeriksaan otomatis di atas. Android belum diaudit kontrasnya selain lewat token yang sama (`tokens.test.ts`).
- **Celah Kanban**: kartu yang dijalankan dan butuh izin tidak punya UI izin di papan; izin hanya muncul di percakapan kartu, dan tidak ada tautan dari kartu ke percakapan itu. Perlu tautan atau panel izin di kartu.
- **Updater**: plugin `tauri-plugin-updater` ditambahkan (dependensi baru, diwajibkan prompt) dengan bagian Pembaruan di Pengaturan. **Rust belum pernah dikompilasi di PC ini** (MSVC tidak terpasang), jadi plugin, `Cargo.lock` (perlu diperbarui oleh build pertama), dan konfigurasinya belum terbukti. Updater tidak bisa mengunduh dari rilis GitHub **privat** tanpa kredensial; keputusan hosting artefak (repo publik terpisah atau server sendiri) ada di `docs/RELEASE.md` dan belum dipilih.
- **omp tidak dibundel** di installer (permintaan prompt: "worker dan omp sidecar"). Worker menemukan omp lewat PATH atau `AIOS_OMP_PATH`. Membundel omp butuh keputusan lisensi, ukuran, dan versi terkunci.
- **Android E2E**: Compose UI test di `apps/android/app/src/androidTest`, dijalankan oleh `pnpm --filter @aios/e2e android` (stack nyata + emulator). Hasil terakhir dicatat di bagian ringkasan fase; belum ada di CI (butuh emulator).
- **Deploy**: `infra/scripts/deploy.sh` diuji dengan perintah palsu di `selftest.sh` (urutan, rollback, dry-run); **belum pernah dijalankan** dengan Docker dan VPS nyata. Rollback hanya mengembalikan image, bukan migrasi.
- **Belum dibuat**: tag `v1.0.0` (menunggu verifikasi di VPS dan perangkat nyata; tag memicu build rilis).

## Ubah dan hapus pesan (setelah Fase 24)

- **Perlu verifikasi di VPS**: setelah percakapan dipotong, gateway membuka sesi Hermes baru (`aios-<percakapan>-<uuid>`) dan mengirim riwayat yang tersisa sebagai `messages` di `/v1/chat/completions`. Diuji dengan Hermes tiruan, belum dengan Hermes 0.22.5 sungguhan. Cara cek: kirim "Nama saya Budi", ubah pesan itu menjadi "Nama saya Andi", lalu tanya "Siapa nama saya?"; jawabannya harus Andi, bukan Budi.
- **Sinkron antarperangkat**: perangkat lain yang sedang membuka percakapan yang sama baru melihat potongan setelah menyegarkan (buka ulang percakapan atau run berikutnya selesai). Belum ada event realtime `conversation.truncated`.
- **Riwayat dibatasi 100 pesan terakhir** saat dikirim ulang ke sesi baru; percakapan yang lebih panjang kehilangan konteks paling awal setelah diedit.
- Run coding (omp) tidak memakai riwayat: omp berjalan `--no-session`, jadi edit/hapus hanya memengaruhi tampilan dan konteks Hermes.

## Lampiran chat (setelah Fase 24)

- **Cara kerja**: klien mengunggah ke `POST /files` (multipart) lalu merujuknya lewat part `file`. Gateway mengubah dokumen (PDF lewat `unpdf`, DOCX lewat pembaca ZIP kecil tanpa dependensi, berkas teks) menjadi teks yang ditambahkan ke prompt (maks 60.000 karakter per dokumen), dan meneruskan gambar inline (`image_url` data URL) ke Hermes. Router dan judul hanya melihat teks pengguna plus nama lampiran.
- **Perlu verifikasi di VPS**: (1) gambar sampai ke model dan dijawab; model Hermes/9Router harus mendukung vision, bila tidak run gagal dengan galat dari provider. (2) Ukuran request ke Hermes dengan gambar sampai 10 MB (base64 ~13 MB) diterima Hermes dan nginx tidak terkait (gateway ke Hermes lewat localhost). (3) Unggah dari aplikasi desktop asli (Tauri plugin-http dengan FormData) belum pernah dicoba di cangkang Rust; E2E memakai shim.
- **nginx**: contoh vhost sudah `client_max_body_size 26m;` (cukup untuk 25 MB + multipart). Pastikan vhost di VPS sama; bawaan nginx 1 MB membuat unggahan besar ditolak 413 oleh nginx.
- **Belum ada**: pratinjau gambar di riwayat (hanya chip nama), unduh ulang lampiran (`GET /files/:id` tidak ada di kontrak), pembersihan berkas yang diunggah tetapi tidak pernah dikirim, lampiran pada run coding (omp mengabaikan gambar; dokumen tetap masuk sebagai teks), dan riwayat yang dikirim ulang setelah edit/hapus pesan hanya membawa teks (isi lampiran lama tidak ikut).
- **Android**: pemilih dokumen sistem (gambar, PDF, DOCX, teks); kamera langsung belum ada.
