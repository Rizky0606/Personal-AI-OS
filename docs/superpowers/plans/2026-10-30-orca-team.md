# Orca Tim Lead + Worker — Implementation Plan

> Implementasi memakai perubahan workspace saat ini; semua perubahan pengguna dipertahankan.

**Goal:** Tambahkan orkestrasi tim project opt-in yang durable, terisolasi per worktree, dapat dihentikan, dan terlihat di desktop serta Android.

**Architecture:** Reuse adapter omp, run coordinator, WorkerRelay, WorktreeManager, pg-boss, serta pola UI/API yang ada. Tambah model/event/API tim dan orkestrasi durable; tidak ubah jalur run tunggal. Tim menyimpan metadata/status di PostgreSQL, file project hanya di worker lokal.

**Tech Stack:** TypeScript strict, Zod, Fastify, Drizzle, pg-boss, React/TanStack Query, Kotlin/Compose.

**Spec:** `docs/ORCA_DESIGN.md` (rekomendasi konservatif dipilih; keputusan terbuka yang belum dipilih memakai opsi paling aman di dokumen).

## Global Constraints

- Team mode opt-in; run tunggal tidak berubah.
- Team state is persisted in PostgreSQL; Lead-only REST/service/replay exist. Durable Worker queue and recovery do not.
- Maksimum satu agent aktif per team sampai enforcement CPU/memori OS tersedia; assignment lain diantrekan. Kapasitas dua Worker belum diaktifkan.
- Resource enforcement (OS CPU/memory, runtime budget termination) is a prerequisite for raising concurrency; current contract permits one active worker.
- Team run ordering, failure-safe cancellation, worker worktrees, approval cleanup, and runtime resource enforcement are unfinished.
- Tidak auto-merge/push; diff per anggota, integrasi final oleh pemilik.
- Team events: `team.created`, `team.member.updated`, `team.review.completed`; replayable.
- Desktop pohon Lead→Worker, stop member/team, agregat approval; Android hanya-baca.
- Semua UI state: loading, empty, error, offline; patuhi token, aksesibilitas.
- Tanpa dependensi baru; typecheck, lint, tes, manual smoke sesuai repo.

## Status workspace dan prasyarat VPS

- Sudah ada: kontrak/API team, tabel/migration, service/routes Lead-only, replay WebSocket, desktop API methods. Belum ada: persistensi team/member sebelum dispatch runner, cancellation tahan kegagalan, orkestrasi Worker, UI team desktop/Android.
- Jangan jalankan tes pada database produksi. `createTestDatabase()` membuat database acak lalu menjalankan `DROP DATABASE ... WITH (FORCE)`. VPS harus menyediakan PostgreSQL/role tes terisolasi dengan izin `CREATE DATABASE`.
- Test integration gateway belum dijalankan karena `TEST_DATABASE_URL` tidak tersedia. Saat DB tes siap, tambah regression tests untuk cancel gagal-safety dan ordering runner, lalu jalankan `pnpm --filter @aios/gateway exec vitest run src/modules/fleets/fleets.integration.test.ts -t "team lifecycle"`.
- Regression ordering harus membuktikan row team/member sudah committed sebelum runner menerima dispatch; kegagalan persistensi tidak boleh dispatch run.
- Setelah tes targeted lulus: gateway typecheck, lint, lalu smoke REST/WebSocket di environment tes. Migration produksi hanya setelah migration diuji di database disposable dan backup tersedia. Jangan auto-merge/push.

## Tasks

1. **Kontrak + persistensi gateway** — tambah Zod schemas/events, tabel/migration, routes untuk create/list/detail/cancel/member cancel, stream team replay, durable pg-boss jobs/recovery. TDD kontrak + integration; preserve existing `/fleets` single-run behavior.
2. **Orkestrasi Lead/Worker + worker isolation** — gateway membuat Lead/assignment runs melalui relay, scheduling hard caps; worker worktree per member, cancellation, cleanup; Lead skill decomposes/reviews, Worker skill accepts bounded assignment. TDD cancellation, queue caps, failure/restart, two fake workers; no adapter-internal async subagent dependency.
3. **Desktop** — launch team opt-in dari project, status tree/activity, team/member stop, pending approval aggregation with individual decisions; API cache/replay. Component/API tests and UI smoke.
4. **Android** — read-only team list/member status via realtime or polling/replay; loading/empty/error/offline; Compose tests/smoke if SDK available.
5. **Integrasi/verifikasi** — API/contract docs, lint/typecheck/tests targeted then full available checks, launch gateway + fake workers and exercise create→two members→cancel/review→reconnect; inspect modified-file scope. No merge/push.
