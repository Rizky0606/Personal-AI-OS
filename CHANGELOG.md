## [1.2.0] - belum dirilis

### Ditambah

- **Memori tersemat**: memori bisa disematkan di Pengaturan > Memori (desktop) dan layar Memori (Android); yang tersemat selalu ikut ke pesan sistem. Kontrak: `Memory.pinned`, `pinned` di `POST`/`PATCH /memories`.
- **`pnpm --filter @aios/gateway eval:memory`**: evaluasi recall memori pada fixture sintetis (60 fakta, 40 kueri) per mode `all` dan `lexical`; recall@12 leksikal kategori "cocok kata" dijaga tes regresi.
- Variabel opsional `MEMORY_RECALL_BUDGET_CHARS` (bawaan 6000) dan `MEMORY_RECALL_TOP_K` (bawaan 12).
- **Ekstraksi fakta memori (slice 3, bawaan mati):** setelah run chat umum dari pesan pemilik selesai, pekerjaan pg-boss `memory-extract` (satu per percakapan, tunda 45 detik) memanggil `MEMORY_EXTRACT_MODEL` sekali dengan teks pemilik saja (bukan jawaban asisten, lampiran, tautan, atau web). Fakta lolos hanya bila kutipannya benar-benar ada di pesan pemilik, tanpa pola injeksi, tanpa rahasia, satu kalimat, dan bukan duplikat (memori, usulan menunggu, yang ditolak/diurungkan 90 hari). Maks 2 usulan per giliran, 20 usulan menunggu, `MEMORY_EXTRACT_DAILY_MAX` panggilan per 24 jam (bawaan 40). Mode `MEMORY_EXTRACT_MODE`: `off` (bawaan), `propose` (usulan + notifikasi `memory_proposal`), `auto` (langsung tersimpan, bisa diurungkan). Project, ruang, tim, dan jadwal tidak pernah diekstrak; gagal ekstraksi tidak mengubah hasil run.
- REST `GET /memories/proposals`, `POST /memories/proposals/:id/approve` (teks suntingan opsional), `/reject`, `/undo` (klaim atomik; `409 proposal_decided`, `409 proposal_not_undoable`, `409 proposal_target_missing`). Migrasi `0019_memory_proposals` (kolom asal di `memories`, tabel `memory_proposals` dan `memory_extractions`).

Izin jaringan ditanyakan dengan "selalu izinkan" per nama tool per project, dan tetap boleh di mode rencana karena hanya membaca. Dinyalakan dengan `MCP_TOOLS_ENABLED=true` (kontrak aditif `run.start.gatewayTools`). Langkahnya tampil sebagai langkah web di Aktivitas dan Progres (desktop dan Android). Desain dan slice berikutnya: `docs/DESIGN_MCP_TOOLS.md`.
- **Tool data `aios_tools` (slice 2):** `memory_list`, `space_search` (metode baru pencarian FTS lintas ruang), `task_list` (hanya kanban project run itu) dan `schedule_list` untuk omp, baca saja, keluaran berpagar sebagai data, maks. 50 butir dan 30 panggilan per run, audit tanpa isi. Worker mengizinkannya tanpa bertanya (juga di mode rencana). Langkahnya tampil sebagai "Membaca data AIOS" dan grup alat "Data AIOS" di Progres (desktop dan Android). Tanpa migrasi; ikut `MCP_TOOLS_ENABLED`.
- **Urungkan memori otomatis (mode `auto`)**: blok "Disimpan otomatis dari chat" di Pengaturan > Memori (desktop) dan layar Memori (Android) dengan tombol Urungkan (`POST /memories/proposals/:id/undo`); memori hilang dan barisnya tampil "Diurungkan". Usulan Hermes (tanpa run dan tanpa percakapan) tetap dikirim, tanpa kunci `conversationId`. Android: ketukan membuka layar Usulan agent.

### Diubah

- **`fallback_model` dihapus dari role dan `RoleInfo`:** tidak pernah dipakai run dan combo-nya tidak ada di 9Router; fallback antar-penyedia dikerjakan combo 9Router.
- **`models.yml` omp bisa diatur per worker:** `AIOS_OMP_REASONING`, `AIOS_OMP_CONTEXT_WINDOW`, `AIOS_OMP_MAX_TOKENS` (bawaan tetap `false`/128000/8192, diukur terhadap 9Router lokal).
- **Recall memori beranggaran** (slice 1 `docs/DESIGN_MEMORI_SEMANTIK.md`): selama bagian memori muat di anggaran, keluaran sama persis seperti sebelumnya; di atas anggaran dipilih yang tersemat, yang cocok kata dengan pesan pemilik (ditambah pesan pemilik sebelumnya), lalu yang terbaru. Memori dibaca sekali per run; `context.used.memory` kini sama persis dengan yang disuntik dan bertambah `total`, `mode`, `items[].via`. Panel Progres menampilkan "Dibaca · N dari M fakta" bila sebagian tidak ikut.
- Migrasi aditif `0018_memories_recall`: `memories.pinned` (bawaan false) dan `memories.tsv` (tsvector `simple`, indeks GIN).
- **Composer desktop**: Rencana dulu, Kerjakan sebagai tim, Cari di web, dan Skill digabung ke satu menu "Opsi"; tab pane menjadi satu pill aktif + dropdown "Ganti tab" bila pane sempit (< 300 px). Perbaikan lanjutan: lint/format, bayangan tab aktif memakai token `shadow-lift`, dan tes mengikuti menu Opsi.
- **Izin tool gateway (BL 918):** judul, tombol, dan petunjuk izin untuk `mcp__aios_tools_*` menyebut tool yang dicakup ("Selalu izinkan untuk `web_search`" dan seterusnya), bukan "izin jaringan" umum. Aturan tetap per nama tool dan tidak berubah; yang diubah hanya teks di desktop dan Android.
- **Label tool browser worker (BL 919):** `mcp__aios_browser_browser_*` tampil sebagai langkah browser di Aktivitas dan Progres, tidak lagi sebagai Konektor. Server `aios_tools` tidak berubah. Kontrak aditif: `AIOS_BROWSER_OMP_PREFIX` di `packages/contracts`.
- **Anggaran web per run bertahan setelah restart (BL 920):** hitungan `web_search`/`web_read` per run dan URL yang sudah diizinkan untuk `web_read` disimpan di `run_web_state` (migrasi `0021_run_web_state`), sehingga restart gateway tidak mengembalikan kuota penuh atau mencabut izin baca di tengah run. Angka anggaran dan kebijakan allowlist tidak berubah; anggaran per jam Hermes tetap di memori.
- **Presisi agent coding** (`docs/DESIGN_PRESISI_AGENT.md`): role `project` kini membawa aturan kerja kode yang pendek dan eksplisit menimpa aturan bawaan omp yang bertentangan: pahami dulu (berkas + pemanggil), diff minimal, protokol perubahan tanda tangan (cari semua pemakai lewat `lsp` references dan grep nama + alias, perbarui semuanya di run yang sama atau jangan ubah tanda tangannya), subagent hanya membaca, verifikasi wajib dengan perintah dan hasilnya, baca ulang diff. Worker menambah bagian "Dependensi worktree" bila worktree punya `package.json` tanpa `node_modules` (bukan mode rencana): agent menjalankan perintah instal sesuai lockfile (`pnpm install --frozen-lockfile`, `npm ci`, …; tanpa lockfile: varian yang tidak membuat lockfile baru) lewat approval, lalu typecheck. Tanpa perubahan kontrak.
- **Bawaan run coding chat project kini `in_place`** (setelan project di worker, bisa diganti ke worktree per project atau per pesan). Tim Orca, armada, kartu kanban, dan jadwal tetap selalu di worktree. Run `in_place` yang berhenti sebelum selesai dengan perubahan berakhir di `needs_review`, bukan `failed`/`cancelled`, dan pesan pemilik berikutnya melanjutkan folder kerja yang sama sampai diterima atau ditolak.
- **Terima dengan merge (mode worktree)**: bila branch pemilik sudah maju, hasil di-rebase ke atasnya lalu fast-forward, dilakukan sebelum worktree dihapus; rebase bentrok dibatalkan dengan `mergeSkipped: conflict` dan branch hasil utuh. Sakelar merge bawaannya nyala untuk run chat.
- **"Cari di web" per percakapan (uji umum B3):** dulu satu sakelar global yang dipersistenkan dan ikut ke setiap chat baru. Kini chat baru selalu mulai mati, nilai berlaku untuk percakapan itu saja, dan chip **Web** (dengan tombol ×) tampil di composer selama menyala. Langkah `cari_web` di Aktivitas menampilkan kueri yang benar-benar dibuat model, bukan potongan pesan.
- **Agent umum tanpa skill inti coding (uji umum B8):** `plan-before-edit`, `verify-before-done`, dan `minimal-diff` kini hanya untuk grup coding. Tulisan kreatif dan pengetahuan umum dikerjakan langsung, dengan catatan "belum diverifikasi" untuk angka atau fakta yang belum pasti, bukan ditolak atau meminta persetujuan rencana.
- **Aturan perilaku semua agent:** jangan menyatakan sesuatu tersimpan, dijadwalkan, diusulkan, atau diingat kecuali alatnya mengembalikan sukses di giliran ini; tanpa itu arahkan ke tombol Ingat atau layar Jadwal.
- **Pesan sistem membawa tanggal dan jam** di zona pemilik (bagian "Waktu" di akhir, supaya awalan prompt tetap sama untuk cache).
- **Pesan sistem agent umum lebih ramping:** tanpa skill inti coding (lihat di atas), `find-skills` hanya ditawarkan lewat indeks, dan kalimat berkas/ZIP yang dobel dibuang. Pesan sistem "Halo": 10.975 karakter (`main` 1.1.x) → 10.018 → 8.850; input Hermes nyata 15.987 → 15.672 token, 13.362 token di antaranya prompt Hermes sendiri (diukur tanpa pesan sistem AIOS), jadi bagian AIOS kini ±2.300 token.
- `rich-answers`: contoh JSON persis per komponen (`chart` memakai field `chart`, bukan `chartType`).

### Diperbaiki

- **Project ikut pindah saat worker didaftarkan ulang (B1, uji project):** desktop yang login ulang mendaftarkan worker baru dan mencabut yang lama; project, run yang didengarkan, tinjauan yang menunggu, dan `workspace.pending` kini pindah ke perangkat baru dalam satu transaksi (audit `project.worker_moved`). REST `GET /projects/:id/worker` (status dari hub worker gateway) dan `PUT /projects/:id/worker` (ikat ulang manual, `409 project_busy` bila ada run berjalan). Sidebar desktop menampilkan worker project menurut gateway, bukan worker lokal, dengan tombol "Pakai worker PC ini".
- **Web bawaan omp tidak lagi melewati izin (B4):** overlay run mematikan `fetch` (baca URL lewat `read`) dan `github`; `web_search` bawaan dimatikan bila `aios_tools` tersedia, selain itu wajib izin jaringan. Tool MCP run tetap jalan saat izin lain menunggu (`waiting_approval`), dan alasan galat tool dialirkan sebagai `tool.output` stderr serta tampil di langkah yang gagal.
- **Baca di luar folder kerja run ditolak (B13):** hook `tool_call` per run dari adapter memblokir `read`/`grep`/`glob`/`find`/`ast_grep`/`lsp` ke `..`, path absolut lain, atau `~`.
- **Izin lebih sedikit dan lebih aman:** perintah baca saja (`git status|diff|log|show`, `ls`, `pwd`, `command -v`, `cat`, `head`) di folder kerja run diizinkan otomatis; "Izinkan tulis berkas untuk run ini" (`ApprovalDecisionRequest.forRun`, `400 approval_scope_invalid`); "Selalu" untuk skrip package manager mencakup argumen relatif setelah `--`. Baris baru tidak lagi dilebur saat mencocokkan aturan, detail izin yang terpotong tidak pernah diizinkan otomatis, dan `.git` dikenali dalam varian huruf/titik/symlink.
- **Pertanyaan baca saja tidak mengunci repo (B12):** run `in_place` baru memegang kunci saat meminta izin tulis, dan melepasnya bila semua izin tulisnya ditolak.
- **`approval.resolved` dan baris izin mencatat `remember` yang sebenarnya (B9).**
- **Narasi antar-giliran asisten dipisah paragraf di adapter (B7).**
- **Pesan commit (B8):** identifier tidak dipaksa huruf kecil, baris dengan huruf non-Latin ditolak, berbahasa Indonesia, dan tinjauan multi-run menggabungkan pesan semua run.
- **Paket skill frontend tidak lagi terpicu kata `page` (B11);** `read-context-first` tidak memaksa membaca AGENTS.md, `find-skills` hanya bila diminta.
- **`Run.endReason`** (`stopped` | `superseded`, migrasi `0024`) membedakan run yang dihentikan dan run yang digantikan pesan lanjutan atau komentar dari selesai/ditolak biasa.
- **Run yang berjalan saat desktop login ulang tidak lagi menggantung `running` (N2, regresi v1.1.8):** `WorkerRelay.moveDevice` dulu memindahkan listener run ke perangkat worker baru lalu menganggapnya tersambung kembali begitu perangkat baru online, padahal proses omp-nya mati bersama worker lama. Kini run itu menunggu bukti dari worker baru: worker mengirim frame baru `runs.active` setiap tersambung, run yang tidak ada di daftar langsung gagal `worker_replaced` (retryable), dan tanpa laporan apa pun tetap gagal setelah masa tunggu putus (60 detik). Hasil `in_place` yang dipulihkan dari `workspaces.json` tetap menjadi `needs_review` lewat `workspace.pending`, tinjauan yang menunggu tetap pindah, dan proses worker yang sama dengan sesi baru tetap melanjutkan run-nya. Worker yang dimulai ulang dengan perangkat sama kini juga mengakhiri run yang hilang (`worker_restarted`) alih-alih menggantung.

- **Tab panel kanan tidak lagi bergulir mendatar:** pilihan antara deret tab penuh dan tata letak ringkas (pill aktif + dropdown "Ganti tab") kini diukur dari ruang nyata di header pane (ResizeObserver, histeresis 8 px), bukan ambang container query 300 px. Dulu, di antara 300 px dan lebar deret sebenarnya (sekitar 325–330 px tergantung label tab aktif, termasuk lebar bawaan 420 px), deret pill meluap dan menampilkan scrollbar. Deret penuh hanya tampil bila muat; fokus keyboard pindah ke padanannya saat tata letak berganti. Isi panel tetap bergulir tegak seperti biasa.
- **Dialog "Branch" project tidak lagi menjanjikan hal yang tidak dikerjakan worker:** teksnya dulu menyebut branch project sebagai dasar worktree tiap tugas dan tujuan merge, padahal worker selalu memakai branch yang sedang checkout di folder project. `defaultBranch` kini disebut apa adanya: label di bilah atas; agent bekerja di branch aktif (ganti lewat tab Git). Sengaja tidak disambungkan ke worker karena mode branch aktif justru memakai branch yang sedang checkout.

- **Grafik `aios-ui` tidak lagi tampil sebagai JSON mentah (uji umum B1):** blok dengan alias umum (`chartType`, `title`, `max`, field tak dikenal) diperbaiki ke skema ketat sebelum validasi, di gateway (disimpan dalam bentuk valid, juga untuk Android) dan desktop (`repairRichAnswer`, satu implementasi di contracts). - **Pensil "Ubah pesan terakhir"** kini mengubah pesan itu di tempat (memotong riwayat lalu mengirim ulang), bukan menyalin teks ke composer (uji umum B4).
- **Stop benar-benar menghentikan Hermes (uji umum B6):** adapter memanggil `POST /v1/runs/{id}/stop` saat dibatalkan atau macet, dan run chat yang dihentikan atau gagal melepas sesi Hermes percakapan; giliran berikutnya memakai sesi baru berisi riwayat dari DB. Hermes mengabaikan riwayat di body bila `X-Hermes-Session-Id` dikirim, jadi riwayat itu dilipat ke pesan user giliran pertama sesi baru; ini juga memperbaiki ubah/hapus pesan yang dulu membuat agent kehilangan seluruh konteks.
- **Satu percobaan ulang otomatis (uji umum B7):** galat `retryable` Hermes (`hermes_stalled`, 5xx, 429) sebelum keluaran apa pun diulang sekali dengan sesi baru; tidak pernah setelah teks, penalaran, atau tool. Orb jawaban yang gagal memakai tanda error.
- Panel Progres di halaman Riset dan Jadwal tidak lagi menyuruh "Tulis pesan".
- **Urutan Output di panel Progres kini pasti** untuk berkas yang dicatat di milidetik yang sama: yang dicatat terakhir di run yang sama tampil duluan (pemecah seri `seq` event), bukan bergantung urutan sort.
- **Galat terima/tolak tinjauan tampil di dalam dialog** (desktop): bila Terima, Tolak semua, Batalkan perubahan file, atau Kembali ke checkpoint gagal, pesannya tampil di dialog yang tetap terbuka (bukan toast 4 detik di belakang overlay) dan menyebut aksi yang belum terjadi ("Perubahan belum dibuang.", "Perubahan belum diterima.", …). `worker_offline` dari gateway kini dijelaskan sebagai worker pemegang folder kerja run yang tidak tersambung, bukan "perubahan belum bisa dibaca". Tombol aksi bisa ditekan lagi untuk mencoba ulang; menutup dialog membuang galat lama.
- **Kartu kanban menunjukkan run yang menunggu pemilik** (desktop): kartu Running kini mengikuti run-nya secara live, jadi run yang menunggu izin tampil "Menunggu izin" (titik peringatan) dengan tombol "Buka run" yang membuka percakapan run tempat izin dijawab; kartu Review menampilkan "Menunggu tinjauan". "Buka run" juga ada di menu kartu dan di dialog kartu yang sedang dikerjakan.
- **Panel izin lebih jelas** (desktop): spawn subagent omp (tool `task`, dikirim adapter sebagai `command`) kini berjudul "Agent meminta izin menjalankan subagent" dengan nama subagent dan tugasnya, bukan "menjalankan perintah". Izin tulis berkas baru (`Path:`/`Content:`) dan ubah berkas (`File:`) tampil seragam: "Berkas: <jalur>", isi baru bisa dibuka. "Selalu untuk project ini" pada tulis berkas kini dijelaskan berlaku untuk semua penulisan berkas di project itu.
- **Run yang dihentikan tidak lagi tampil "Selesai"** (desktop): run yang dihentikan pemilik tetapi sudah mengubah berkas (`needs_review` dengan `Run.endReason = stopped`) kini berringkasan "Dihentikan" dengan Orb kotak redup, banner tinjauannya memperingatkan bahwa hasilnya mungkin setengah jadi, dan daftar run Project menulis "Dihentikan, perlu ditinjau". Run yang digantikan pesan lanjutan atau komentar ke agent (`rejected` dengan `endReason = superseded`) tampil "Dilanjutkan di run berikutnya", bukan "Ditolak". Tandanya dari gateway (`Run.endReason` dan `run.status.endReason`), jadi berlaku di semua perangkat desktop; catatan localStorage sementara (`stoppedRuns.ts`) dihapus.
- **Run hening punya penanda** (desktop): bila run berjalan lebih dari 15 detik tanpa event baru (tidak ada tool yang berjalan, izin, atau pertanyaan yang ditunggu), baris aktivitas menampilkan "Menunggu model · N dtk sejak aktivitas terakhir".
- **Rapikan UI chat project dan sekitarnya** (desktop): topbar chat project berjudul nama project (bukan "Project") dan chip project hanya menampilkan branch; chip topbar tidak lagi terpotong ("Proje…", "Model oto…") melainkan yang tidak muat disembunyikan menurut prioritas. Tab Diff yang kosong di chat (umum maupun project) menawarkan "Tulis pesan", bukan "Buka papan kartu". Sidebar Kanban hanya meminta memilih project bila belum ada yang dipilih. Sidebar Kelola project yang kosong (latar dialog Tambah project) berupa petunjuk tanpa tombol "Coba lagi". Katalog komponen dev memuat panel izin, Orb dihentikan, dan baris run hening.

- **Thumbnail bukti**: screenshot dan SVG dari tool agent tampil sebagai thumbnail di baris aktivitas dan panel Progres; lightbox dengan Esc untuk menutup.

### Diperbaiki

- **Balapan `review.apply` vs run selesai** (worker): klien yang melihat run "selesai" lalu langsung menerima/menolak hasil bisa ditolak diam-diam (`run_active`) tanpa worktree pernah terhapus. Flag internal kini berubah serentak dengan event penutup, bukan menunggu pembersihan proses selesai.
- Tes harness dsh (`dshTestIdentity`) yang salah mensimulasikan "bukan root" saat benar-benar dijalankan sebagai root di Linux (ditemukan saat verifikasi gerbang P8; tidak memengaruhi kode produksi).
- Deretan perbaikan bug kecil P3 (lebar input `TextField`, label kuota sidebar, keterangan model dari data server, pemilih model dinonaktifkan untuk Hermes, xterm menunggu font siap) dan P4b (mesin dipaksa, chip agent di Topbar, `ProjectList` mati dihapus).
- **Balapan status tim Orca** (gateway): tim dilaporkan `completed` sebelum rencana Lead tersimpan, sehingga panel berhenti memoll dan menampilkan "Tim selesai." tanpa tugas (penyebab flake `team.spec`).
- Parser `SKILL.md` menolak skill publik yang `description`-nya ditulis sebagai skalar YAML bertingkat; daftar skill Hermes terpotong diam-diam di 300 entri (kini batas 2000 dan pemotongan diberitahukan).
- **Deploy otomatis VPS tidak pernah berjalan**: `infra/scripts/auto-deploy.sh` tersimpan di git tanpa bit eksekusi (mode 100644), sehingga `aios-deploy.service` gagal `203/EXEC` setiap 10 menit sejak timer dipasang (2026-10-27). Mode diperbaiki menjadi 100755; `infra/scripts/selftest.sh` kini memeriksa bahwa setiap skrip yang dipanggil `ExecStart` unit di `infra/systemd/` bisa dieksekusi. Akibatnya, setelah perbaikan ini terpasang di VPS, timer benar-benar men-deploy tag rilis baru secara otomatis.

### Diketahui

- dsh sebagai root belum terbukti bekerja ujung-ke-ujung di CI Docker/VPS produksi (hanya diverifikasi di satu mesin pengembangan Linux dengan kendala tata letak folder yang spesifik mesin itu). Hermes dan dsh **nyata** (bukan tiruan) belum pernah dicoba dalam alur pengguna lengkap sejak P5 (Hermes) dan sama sekali (dsh). Lihat `docs/BACKLOG.md` "Ringkasan status gerbang P8" untuk daftar lengkap blocker/penting/nanti.
- Sudah digabung ke `main` (`b26d61e`). Gateway dari commit itu (tag otomatis `v1.0.46`) sudah di-deploy ke VPS pada 2026-11-15 setelah backup (snapshot restic `0bed8dcf`): migrasi 0011–0017 diterapkan, `/v1/readyz` ok. Tag `v1.1.0` diterbitkan oleh rilis ini (lihat `docs/RELEASE_NOTES.md`).
- Skill (P9–P11): ketepatan pemilihan skill belum diukur ulang setelah perbaikan nama indeks; `propose-skill` belum diuji terhadap model sungguhan; kurator dan pemantau Hermes belum dijalankan terhadap pg-boss produksi; Android tanpa layar usulan. Lihat `docs/BACKLOG.md` "Temuan P9" sampai "Temuan P11".
